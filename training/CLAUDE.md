# training/ context

Loaded automatically when working under `training/`. See the root `CLAUDE.md` for everything else.

## SLM fine-tuning pipeline

Everything training-related — dataset generators, Kaggle/Colab notebook scripts, benchmark tooling, and the generated `.jsonl` datasets themselves — lives under `training/` (`training/tools/`, `training/data/`), deliberately separated from the runtime ecosystem so it reads as its own self-contained sub-project. `config/intents.json` and `config/grammars/intent_schema.gbnf` stay in `config/` regardless, since both are also consumed at runtime (`nlp/clIntentEngine.py`, `nlp/clSLM.py`) — only `training/tools/gen_dataset.py` writes to the latter. A dedicated `training/.venv` (or `.venv-train` before it's relocated) holds the heavy training-only dependencies (`torch`, `unsloth`, `bitsandbytes`, `trl`, `peft`, `accelerate`) — kept out of the main ecosystem venv entirely, since runtime inference only ever needs `llama-cpp-python`, not a training stack.

There are two separate models: the **action model** (Qwen2.5-0.5B-Instruct, grammar-constrained, classifies intent into `action_id`/args) and the **reply model** (SmolLM2-360M-Instruct, no grammar, phrases a spoken JARVIS-voiced confirmation for an already-decided action). A change to `config/intents.json` — a new intent, a changed template — generally needs both models regenerated and retrained together, since the action model's grammar and the reply model's phrase bank both key off the same intent set.

1. `python training/tools/gen_dataset.py` — regenerates **both** `training/data/synthetic_lora_dataset.jsonl` and `config/grammars/intent_schema.gbnf` (the action model's inputs) from `config/intents.json` in one pass. These two outputs must stay in lockstep, so the `.gbnf` file is auto-generated and headed "do not hand-edit" — its `action_id`/`action` enums are derived directly from `intents.json`. Change intents, then re-run this script; never hand-edit the grammar.
2. `python training/tools/gen_reply_dataset.py` — regenerates `training/data/reply_lora_dataset.jsonl` (the reply model's input) from `config/intents.json` plus its own hand-written `PHRASE_BANK`/`SLOTTED_PHRASES`/`FOLLOWUP_PHRASES` in the script. A new intent needs a `PHRASE_BANK` entry here to get a spoken confirmation at all; without one it's silently skipped. `training/tools/listen_reply_samples.py` plays samples from this dataset aloud (matching the live TTS voice exactly) to judge phrasing/tone before committing to a retrain.
3. Training — either copy cells into a Kaggle (or Colab) notebook, or run locally against a CUDA GPU using `training/.venv`:
   - `training/tools/kaggle_train_all.py` — trains **both** models in one run (action model, then frees GPU memory, then reply model); the normal path when both datasets changed together. On Kaggle/Colab, needs both `.jsonl` files added as notebook inputs; run locally, it finds them under `training/data/` automatically.
   - `training/tools/kaggle_train.py` / `training/tools/kaggle_reply_train.py` — the same two phases as standalone scripts, for retraining just one model.
4. `python training/tools/benchmark_slm.py` — runs `training/data/benchmark_suite.json` against the action model's GGUF under `config/grammars/intent_schema.gbnf` (grammar-constrained decoding via `llama-cpp-python`) and reports per-category pass rates. Run this before promoting a new GGUF into `config/core.json`'s `slm_settings.model_path` (the reply model has no equivalent pass/fail benchmark — judge it by ear via `listen_reply_samples.py` instead, and point `reply_slm_settings.model_path` at it once trained).

## Model config

- The live daemon's SLM model path is `config/core.json` → `settings.slm_settings.model_path`, independent of the hardcoded `MODEL_PATH` in `training/tools/benchmark_slm.py` — keep both pointed at the same GGUF when swapping in a newly trained model.
- Both `slm_settings` and `reply_slm_settings` in `core.json` also carry a `model_url` — if `model_path` isn't present under `models/` at boot, `nlp/clSLM.py`'s `ensure_gguf_exists()` downloads it from there (e.g. a Hugging Face `resolve/main/...` link). Neither GGUF is a stock model, so there's no hardcoded fallback URL; an empty `model_url` with a missing file just disables that engine with a clear log message instead of crashing.

- **Fast decode**: at runtime `nlp/clSLM.py` decodes freely and validates against the schema parsed from `config/grammars/intent_schema.gbnf` (`nlp/clIntentSchema.py`), re-running under the grammar only on invalid output — the grammar is ~4x slower per token. So the grammar file must stay the single source of truth for what is valid, and after training a new GGUF run `python training/tools/compare_slm_decoding.py` alongside the benchmark to check free output is still ~99% valid and matches the constrained answer.

## Local voice training (Piper fine-tune, in WSL2)

Goal: a small Piper voice trained on the real Ryan lines (the cached `assets/tts_*.mp3`, generated by edge-tts `en-GB-RyanNeural` at +27% rate / -5 Hz — the voice JARVIS used to have), replacing the generic `en_GB-aru-medium` in `models/piper/`. Runtime stays the plain Piper engine (~300 MB while speaking); only training needs PyTorch, and only inside WSL.

- **Status: environment deleted (2026-10-12).** The WSL `~/voice/` folder (training env, checkpoints, exported voices), `uv` and its caches, `data/voice_training/`, and the raised `.wslconfig` are all gone; `.wslconfig` is back to `memory=2GB`. To retrain, rebuild: install `uv` in the Ubuntu, clone `OHF-Voice/piper1-gpl`, create a Python 3.11 venv, install torch 2.11.0 from the `cu128` index, fetch the Alan checkpoint with `voice_fetch_base.sh`, and rebuild the clips with `voice_clean_data.py` from the cached `assets/tts_*.mp3` (still in `assets/` unless the cache cleaner purged them; more lines need edge-tts working again). Clips were `file.wav|text` in `metadata.csv`, Whisper-transcribed.
- **WSL needs RAM**: training used `memory=10GB` in `%USERPROFILE%\.wslconfig` (restore to 2GB + `wsl --shutdown` afterwards).
- **Control** (`training/tools/voice_job.py` on Windows → `voice_ctl.sh` in WSL; jobs are PID files in `~/voice/jobs/`): `python training/tools/voice_job.py status | pause | resume | stop | game | release | start <job> <cmd...>`. `pause` freezes the whole process tree (CPU/disk stop at once) **but a frozen CUDA process keeps its VRAM**, so before gaming use `game` (stops jobs, shuts WSL down: no GPU memory, no WSL RAM) — training restarts from its last checkpoint (`--ckpt_path`). Resumable downloads: `training/tools/voice_fetch_base.sh` (curl -C -). On Git Bash, set `MSYS_NO_PATHCONV=1` when an argument is a `/home/...` path or it gets rewritten.
- **What actually works here** (the official recipe in piper1-gpl `docs/TRAINING.md` needed these fixes): scripts `training/tools/voice_train.sh <epochs> <run>` (set `RESUME=<ckpt>` to continue a run), `voice_run_train.py` (wrapper), `voice_export.sh <run> <ckpt> <voice>`; run them in WSL as `voice_job.py start <job> bash <script> ...`.
  - The Alan checkpoint is the *old* Piper format, so `--ckpt_path` fails on its hyperparameters; use `--model.warmstart_ckpt` (non-strict weight copy, fresh optimizer) with `--model.use_mrd false`. `--ckpt_path` is only for resuming our own runs.
  - Use `--data.espeak_voice en-gb-x-rp` (what the base voice was trained with; plain `en-gb` doesn't exist in the bundled espeak data). Batch size 8 takes ~5.8 GB VRAM (~18 s/epoch for 159 clips).
  - `voice_run_train.py` allowlists `pathlib` types for torch's safe loader and replaces the default checkpoint callbacks (the stock `val_mos` monitor raises when the MOS predictor doesn't log): best 3 by `val_mel`, `last.ckpt`, and a snapshot every 100 epochs. Pick the final checkpoint by listening, not by loss.
  - The Cython alignment extension builds with `./build_monotonic_align.sh`; the `espeakbridge` native module can't be built (no g++), so copy `espeakbridge.so` and `espeak-ng-data/` from the PyPI `piper-tts==1.8.0` Linux wheel into `piper1-gpl/src/piper/`.
  - Export needs `onnxscript` and the legacy exporter (`torch.onnx.export(..., dynamo=False)`, patched in `voice_export.sh`); the config written during training must be copied next to the model as `<voice>.onnx.json`.
- **Outcome (see `docs/voice_latency_plan.md`)**: the best result from 159 clips was still glitchy next to the real recording, so the voice is parked. Extra tools: `voice_clean_data.py` (rebuild the clips from the mp3s), `voice_avg.sh` / `voice_blend.sh` (checkpoint averaging / blending with the base), `voice_say.sh` (ONNX) and `voice_say_torch.sh` (straight from a checkpoint, no export). **Never judge a voice while a training job runs** — it starves audio output and words cut at random even for known-good voices; `voice_job.py pause` first.
- **Licence**: the training audio is Microsoft's neural voice output — personal use, the trained model stays in gitignored `models/`, never published.
## Voice dataset (custom TTS voice)

`python training/tools/collect_voice.py` builds a clean LJSpeech-style dataset of the user's own voice (`capture` of the PC's own playback — parec monitor on Linux, WASAPI loopback via optional `PyAudioWPatch` on Windows; `record` from the mic with guided prompts or `--free`; `import` from audio/video files on disk, optional `--transcribe` via faster-whisper, `review` to listen, fix transcripts and cut clips (`cut` does the same standalone), `dedupe` for repeated audio, `move IDS --to NAME` to set clips aside in another dataset folder (same layout, e.g. `training/data/ultron_lines/`, gitignored) so enroll/filter/export never see them, `enroll` + `filter` to keep only one speaker via a Wespeaker ONNX model auto-downloaded into `models/` (a clip's score is the mean similarity to its 3 nearest enrolled clips, not to one average voice, because one speaker sounds different quiet vs loud or on another mic; the threshold sits 2.5 robust-MADs under the typical leave-one-out score; `enroll` again after the dataset grows, `--ids` to pin it to verified clips; `voiceprint.old.npz` is the previous single-centroid voiceprint)) into `training/data/voice_dataset/` (gitignored). It's standalone — nothing at runtime reads it. **`src/utils/clVoice.py` (Piper + effect chain, from the laptop) is not wired into `src/clTTS.py`** (the streaming engines in `utils/clTTSEngines.py` don't use it); `settings.tts_settings` is only read by `clVoice` itself, so it is absent from `core.json` here.

**Training the voice.** `python training/tools/export_piper_dataset.py` packages the clean clips (two-column `file.wav|text` metadata, which is what Piper expects — a third column makes it read the set as multi-speaker) into `training/data/voice_export/piper_voice_dataset.zip` (gitignored, like the dataset). `--deep PERCENT` keeps only the deepest share of clips by median pitch (a percentile of the data, so it adapts to the voice; leaves out the high, excited clips). Upload that zip as a Kaggle dataset and paste `training/tools/kaggle_piper_train.py` into a T4 notebook: it fine-tunes Piper's stock `ryan` medium checkpoint with `--model.warmstart_ckpt` (not `--ckpt_path`: that re-reads the old checkpoint's hyperparameters, which the current Piper rejects, e.g. `model.sample_bytes`; the warm start copies the matching weights and starts epochs at 0, so `--trainer.max_epochs` is just `EXTRA_EPOCHS`; PyTorch >= 2.6 also needs the `run_module.py` launcher to load the old checkpoints), exports every saved checkpoint to ONNX and renders test sentences so the best one can be picked by ear. To refine an already-trained voice, set `CONTINUE_FROM` in the kaggle script to its weights `.ckpt` (e.g. `lightning_logs/snapshots/epoch=300-snapshot.ckpt` from the same session; the ONNX can't be resumed, and `/kaggle/working` is wiped when the session ends): it warm-starts from those weights with a gentler learning rate and fewer epochs. Put the chosen `.onnx` + `.onnx.json` in `models/piper/` and point `settings.tts_settings.piper_model` at it. The kaggle script was written from Piper's docs/source and has not been run on Kaggle yet. Train on the clean clips; the effect (`src/utils/clVoice.py`) is applied after synthesis, preceded by a spectral-gate `denoise` (`tts_settings.denoise`, 0-1, default 0.6; its noise profile is the quietest frames of each phrase) because the trained voice inherits its clips' background noise. `collect_voice.py review --fx` previews clips with the live effect (same chain and `settings.tts_settings.fx` as the TTS, pitch shift and reverb tail included; review marks stay in the original clip's time) and `fx-sync` fills `voice_ref/fit_preview/mix30/` with effect copies of every clip, re-rendering all of them when the effect settings change.
