# Voice pipeline (mic → Whisper → Daemon → TTS)

Read when touching `clMic.py`, `clWhisper.py`, endpointing, or anything that changes how fast a spoken command is answered. Speech output (`clTTS.py`) is in `daemon-routing.md`.

- **Endpointing** (`clMic.py` `_record_command`): once the wake word / active window / PTT starts a recording, the command ends when a neural endpointer says so — `utils/clVad.py` `SileroVad` (the 1.8MB `silero_vad.onnx` that ships inside openWakeWord; one CPU thread, no extra dependency) scores each 80ms chunk, and `utils/clEndpointer.py` `Endpointer` (pure logic, no audio) turns scores into started / ended / timed-out. The command ends after `end_silence_ms` (default **700**) of non-speech; hysteresis (`speech_threshold` 0.5 to start, 0.15 lower to stay speaking) and a 160ms minimum keep clicks and breaths from starting or extending a command. PTT holds the recording open regardless. The old volume-threshold logic (RMS window + "flatline" rule, ~1.6–2.1s of dead time after you stop) is still there as the fallback when Silero can't load or `vad_settings.engine` is `"rms"`.
- **Config** (`config/core.json` → `vad_settings`, all optional): `engine` (`silero`|`rms`), `end_silence_ms` (raise it if you get cut off mid-sentence on pauses; lower it for snappier commands), `speech_threshold`. `attention_mode_multiplier` is the same section's older RMS-only knob.
- **Not changed by the endpointer**: the wake-word gate (`current_rms > a_thresh` decides whether openWakeWord runs), attention-mode triggering, and the RMS volume meter — those still use the volume thresholds.
- **Latency trace**: every command logs `[LATENCY] endpoint=… wire=… whisper=… route=… action=…` (see `daemon-routing.md`). `endpoint` is last-speech → mic dispatch; with Silero it should sit near `end_silence_ms` (~0.8s measured on synthetic speech) instead of ~1.5–2.2s. Compare it after any change here.
- **Tests**: `tests/test_clEndpointer.py` (logic), `tests/test_clVad.py` (real model: silence/noise/chunk carry-over), `tests/test_clMic.py::TestRecordCommandEndpointing` (the real recording loop with scripted scores). Speech-detection quality itself can't be unit-tested without real audio; verify by ear and by the `[LATENCY] endpoint=` numbers.
- **Fast path vs SLM gate** (`clDaemon.py` `_is_complex_request`): a command goes to the ~1s SLM first only if it looks compound or corrective — an ellipsis, a second sentence, 2+ commas, a correction word (actually/instead/I mean/…), more than 8 words, or more than one action verb. Whisper's closing period and a single natural-pause comma do **not** count (they used to, which sent nearly every command to the SLM). The fuzzy matcher still has to clear its 80 threshold to answer; a miss falls through to the SLM as before.
- **Whisper decoding** (`clWhisper.py`): `temperature=0.0` — a single greedy pass. The default 0.0→1.0 ladder re-decoded up to six times on low confidence (common for a short command after the wake word) and caused the 2–4s outliers; the second language's pass is the second opinion instead. Silence trimming was measured and rejected: faster-whisper pads every clip to a 30s window, so a shorter clip costs the same, and `wav`/`queue`/`wire` in the latency line are all ~0.
- **Reply blip** (`clTTS.py` `_load_blip_audio`): `assets/blip.mp3` starts with ~0.6s of silence; it is decoded once, the lead-in cut (0.96s → 0.36s) and played as an in-memory sound on its own mixer channel. There is no fixed wait before it any more — Spotify ducking (triggered by `tts_state: active`) runs while it plays.
- **Interrupting JARVIS while it speaks (barge-in)**: three layers, so it works on any hardware.
  1. *Wake word over the speech* (`clMic.py` `_barge_in_step`): while `tts_busy`, the mic keeps listening instead of draining. `clTTS.py` publishes exactly what it plays on `jarvis/sys/tts_ref` (16 kHz int16 chunks with a wall-clock `t0` + sample `off`set — gain applied, blip included); `utils/clEcho.py` `ReferenceBuffer` stores it by time and `EchoCanceller` (pyaec/Speex, **one** pass — two distort the voice) subtracts it from the mic, then openWakeWord scores the cleaned audio. A score > `wake_threshold` (0.6, one chunk — requiring two in a row missed most interruptions and prevented no false stop) sends `jarvis/sys/tts_stop`, and the recording starts from ~1.5 s of cleaned audio before the trigger. Stale `idle`/`request_reply` from the interrupted reply are ignored for 2 s (`bargein_hold_until`) so they can't drain the stream or open a follow-up window.
  2. *Keys*: the PTT key (`ptt_start`/toggle on) stops speech first; the abort keybind publishes `jarvis/sys/abort`, which `clTTS.py` handles by bumping its abort counter and stopping generation and playback.
  3. *Volume limiter* (`utils/clEchoGuard.py` `EchoGuard`): echo cancellation has a ceiling — measured on recordings of this setup re-mixed at stronger echo, it catches the wake word up to a speaker ~3× louder than the user's voice at the mic (2/3 at +10 dB, 3/3 at 0 dB), nothing at 10×. So after each uninterrupted reply the mic compares JARVIS's level at the mic (75th percentile of mic rms during the reply, room noise removed) with the median level of the user's commands (default 0.03 until 3 are heard) and, if the echo/voice ratio is above `target_esr_db` (+4 dB), lowers only JARVIS's own TTS gain (≤ 6 dB per reply, floor 0.1, raised again when there is room) via `jarvis/sys/tts_control` `set_gain`, announcing it once per boot. State persists in `data/barge_in_state.json`. `settings.barge_in.auto_limit = false` turns the limiter off.
  - Config (`core.json` → `settings.barge_in`, all optional): `enabled` (true), `auto_limit` (true), `wake_threshold` (0.6), `hits` (1), `target_esr_db` (4.0). Without `pyaec` there is no cancellation (the wake word alone still works on quiet speakers).
  - Cost: ~0.45 ms of CPU per 10 ms of audio, only while JARVIS is speaking. The filter keeps its state between replies, so the first second or so of a reply can be missed while it converges.
  - Tests: `tests/test_clEcho.py` (buffer, canceller on a synthetic echo, seam-exact stream resampler, limiter), `tests/test_clMic.py::TestBargeIn`, `tests/test_clTTS.py::TestEchoReferenceAndGain`. Acoustic performance can't be unit-tested: it was measured by replaying real recordings through `_barge_in_step` with a virtual clock (see git history of this note for the numbers).
- **SLM fast decode** (`nlp/clSLM.py` `_infer_sync`, `nlp/clIntentSchema.py`): the GBNF grammar costs ~36–40 ms per generated token (the sampler walks the 150k-token vocabulary each step) vs ~8 ms free, so a command took 650–900 ms (2.1 s for two actions). The model now decodes **freely** and the result is used only if `IntentSchema` (built from `config/grammars/intent_schema.gbnf` itself, so it follows `intents.json` regenerations) says it is exactly what the grammar would allow; otherwise the call is re-run under the grammar (rare: ~1%, and then slower than before). Measured: 296 prompts (benchmark suite + training-data sample + real/noisy phrases) → 99.0% valid on the first try, identical to the constrained answer except sampling noise (temperature 0.1); now 177–370 ms for single actions, ~580 ms for two. `slm_settings.fast_decode: false` restores always-constrained decoding. After retraining or changing intents, re-run `python training/tools/compare_slm_decoding.py` (reports valid-rate, agreement, speed). Not fixed by this: the model sometimes mishears into a valid-but-wrong action under either mode ("post music" → play).
- **Wake-word clean-up** (`clDaemon.py` `sanitize_transcription` / `strip_wake_word` / `_is_wake_token` / `_collapse_repeat`): before routing, a leading "jarvis" — however Whisper rendered it — is stripped so the command can hit the fast path. `_is_wake_token` accepts spelling ratio ≥ 75, the same metaphone, or the same consonants give or take one with a "j-like" first letter and a final s ("tervis", "hrvs", "jarvs"; "nervous"/"serves" are rejected). It only counts at the start, after at most two greeting/hesitation words (`_WAKE_PREFIXES`: hey, hi, ok, okay, no, new, now, oh, yo, so, um, well, …). A bare "No, Jarvis." / "New Jarvis" (nothing after the name) is deliberately **not** stripped — it is a decline, not a wake word. `_collapse_repeat` reduces "X hey jarvis X" (the mic caught the command twice around the wake word) and exact "X X" stutters of ≥ 6 words to one copy; different or short phrases are left alone. Both transformations run in `sanitize_transcription`, so the voice handler and `route_voice_command` agree.
