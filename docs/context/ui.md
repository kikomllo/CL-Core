# Dashboard UI

Read when working on `src/clUI.py` or `src/ui/*Widget.py`. The Claude widget specifics are in `docs/context/claude-bridge-widget.md`.

- **UI** (`src/clUI.py`, PyQt6, plus `src/ui/*Widget.py`) is a separate desktop app that talks to the rest of the system purely over MQTT (`paho-mqtt`) — treat it as just another decoupled client, not part of the daemon process.
- **Dashboard window-flag parity** (`src/clUI.py`): the fullscreen dashboard no longer sets `WindowStaysOnTopHint` on Windows — that was only safe alongside a Windows-only background occlusion detector that auto-collapsed the dashboard back to overlay mode whenever another window came to the front, which has been removed so both platforms behave the same: fullscreen is left only via an explicit user action (keybind/voice), never automatically. The small idle overlay widget's click-through is applied immediately in `__init__` on both platforms now — Linux via Qt's `WA_TransparentForMouseEvents`/`WindowTransparentForInput` attributes, Windows via the `_set_win32_click_through` helper's raw `WS_EX_TRANSPARENT` toggle (Qt's attribute doesn't reliably apply on Windows combined with `WindowStaysOnTopHint`+`Tool`) — previously the Windows toggle only ran inside the `set_ui_mode("set_overlay")` transition, so it wasn't click-through until the first fullscreen↔overlay round-trip.
- **Closed widgets remember their geometry for the session.** `close_draggable_widget` destroys the wrapper, so its position drops out of `active_widgets` and the next `ui_state.json` save; `_closed_widget_geometry` stashes pos/size before destroying, and `spawn_widget` prefers it over centering. Session-lifetime only, not persisted to disk.
- **Media widget** (`src/ui/clMediaWidget.py`, two live copies: the dashboard widget and the calendar carousel's — `clUI.py` feeds both): the header is the badge followed by shuffle and repeat (bare icon + on-dot, no circle — `DotToggleButton(circle=False)`); the transport row is prev/play/next; the progress bar is a clickable `SeekBar` (still a 0–1000 `QProgressBar`; thicker track and knob on hover, no time tooltip); and a bottom row of three circles — Up Next, lyrics (middle, slightly bigger), App Volume — replaced the old full-width "App Volume ▾" tab. `DotToggleButton` is hand-painted so the on-dot can sit under the icon; `centered=False` drops the room above it (used where vertical padding matters: the bottom row and the header, whose badge is top-aligned to share the icons' centre line). Up Next and App Volume are drawers that grow the wrapper downward through the same `_toggle_drawer` delta logic (one open at a time; `_app_volume_delta` is shared by whichever is open; use `isHidden()`, not `isVisible()`, for drawer state). Shuffle/repeat/`can_seek` arrive in `media_status`; a click flips the button optimistically and holds a dimmed icon with a hollow dot until a status carries the requested value (or ~2.5s), so a stale status can't flip it back. Up Next is fed by the retained `jarvis/sys/spotify_queue`; opening the drawer sends `queue` (free when `clSpotify.py` already follows the queue) and its refresh button sends `queue_refresh` (the only call that costs a Web API request). Minimum width is the widest of every state (`_measure_drawers_min_width`, from throwaway sample rows, so it's the same before any data arrives): opening a drawer never widens the widget. Minimum *height* still follows the open drawer on purpose. Known, pre-existing: after App Volume rows arrive the wrapper grows to its preferred height but only the tracked delta is removed on close, so it can end up taller than before (reproduces on the original code); the grow-only `DraggableWidget` logic owns that. Backend details: `docs/context/cross-platform.md`.
- **Clock** (`src/ui/clClockDisplay.py`, `ClockDisplay`): date and time centred above the visualizer's orb in fullscreen — the time's box starts 258 px down at 1080p (scaled), 84 px digits, seconds small at the right, a fading hairline, then the date line (design: the "Dashboard Clock" artboard). A plain child of `JarvisUI` created right after the visualizer (stacks above it, below every widget made later), hand-painted (Qt has no text-shadow blur, so the glow is a real gaussian — `gaussian_blur` in numpy over a mask of the digits, two layers — computed once per minute and cached; an earlier version repeated the text at a few radii and the opacity steps were visible), transparent to the mouse, and its timer (aimed at the next second, or minute with seconds off) only runs while it's shown. `refresh_layout` places it; `set_ui_mode` shows it with the fullscreen layout and hides it with the overlay square and during a monitor swap. The colon is deliberately steady (tested). `core.json` → `settings.clock_settings` (all keys optional; wrong types fall back): `enabled`, `hour24` (default true), `seconds` (true), `language` (`en`|`pt`, default `en`), `glow` (0–3, default 1.0: the halo behind the digits; 0 turns it off). Idle waves never reach it, but a loud peak (waves up to y≈270 at the app's maximum amplitude) can pass behind it — it stays on top.
- Persisted UI state (`data/ui_state.json`) is a single shared file, not per-display — don't point test instances of `clUI.py` at it. `tests/test_clUI.py` enforces this with an autouse `isolated_state_file` fixture that redirects `clUI.STATE_FILE` to a tmp path for every test; before it, several classes only patched it around part of their body and a pytest run left a default-sized, centered To-Do widget in the real file, which the live UI restored as open on its next restart. A new UI test file that constructs `JarvisUI` needs the same isolation.
