# Dashboard UI

Read when working on `src/clUI.py` or `src/ui/*Widget.py`. The Claude widget specifics are in `docs/context/claude-bridge-widget.md`.

- **UI** (`src/clUI.py`, PyQt6, plus `src/ui/*Widget.py`) is a separate desktop app that talks to the rest of the system purely over MQTT (`paho-mqtt`) — treat it as just another decoupled client, not part of the daemon process.
- **Dashboard window-flag parity** (`src/clUI.py`): the fullscreen dashboard no longer sets `WindowStaysOnTopHint` on Windows — that was only safe alongside a Windows-only background occlusion detector that auto-collapsed the dashboard back to overlay mode whenever another window came to the front, which has been removed so both platforms behave the same: fullscreen is left only via an explicit user action (keybind/voice), never automatically. The small idle overlay widget's click-through is applied immediately in `__init__` on both platforms now — Linux via Qt's `WA_TransparentForMouseEvents`/`WindowTransparentForInput` attributes, Windows via the `_set_win32_click_through` helper's raw `WS_EX_TRANSPARENT` toggle (Qt's attribute doesn't reliably apply on Windows combined with `WindowStaysOnTopHint`+`Tool`) — previously the Windows toggle only ran inside the `set_ui_mode("set_overlay")` transition, so it wasn't click-through until the first fullscreen↔overlay round-trip.
- **Font: JetBrains Mono** (SIL OFL), bundled in `assets/fonts/` and registered by `clUI._load_bundled_fonts()` so both machines render the same glyphs. `Theme` is the single source: `FONT_NAME`, `FONT_FILES` (to bundle another weight, add the file here), `FONT_FALLBACKS`, and `FONT_FAMILY` for stylesheets. Don't hard-code a family anywhere (code that did, e.g. `"Courier New"`, ignored the theme). It has ~13% taller line spacing than the DejaVu Sans Mono it replaced, so fixed-height widgets need a little headroom. `clTrayIcon.py` still draws its glyph in Arial: it runs in its own process, which never loads the bundled fonts.
- **Rounded borders are painted by `src/clSmoothBorders.py`, not by Qt.** Qt's QSS draws a `border` on a rounded widget from clipped arc segments (stepped, lopsided corners; worst pixel ~135/255 off an ideal corner; a fill with no border is fine, ~13). The 1920x1080 / 100% monitors have no spare resolution to hide it. The engine hooks every `QWidget.setStyleSheet` (via `clUIScalerInjector`) plus `QPushButton`/`QLineEdit` creation (the global stylesheet styles those with no per-widget sheet). For a widget whose cascade (application < ancestors < own sheet; `parse_css`/`resolve` handle `Type#id:pseudo` selectors and bare declarations only) gives it a radius and a solid border, the sheet handed to Qt gets a marked override block making the border colour `transparent` (same width, so layout is unchanged), and the widget's `paintEvent` is wrapped to paint the border afterwards as one AA ring path, per state (hover/pressed/checked/disabled/focus) and per side (the event cards' thick orange left edge). Gotchas: the override selector must be `QWidget#name` placed last (it ties on specificity and wins by order; a repeated id or an attribute selector does NOT raise Qt's specificity); `styleSheet()` returns the sheet with the block, so callers that re-read it are fine (`_OVERRIDE_BLOCK` strips it on the next set); widgets given no `objectName` get `sbN`; margins, non-solid borders, gradient border colours and `QTextEdit`/scroll areas are left to Qt. Debug switch: `JARVIS_SMOOTH_BORDERS=0` turns it off. Small circles are hand-painted instead: `ui/clRingCheckBox.py` (`RingCheckBox`, the To-Do checkbox: 8x supersample, box-filtered, cached) and `DotToggleButton` in `clMediaWidget.py`. A new rounded widget needs nothing special; just don't draw its border any other way.
- **Closed widgets remember their geometry for the session.** `close_draggable_widget` destroys the wrapper, so its position drops out of `active_widgets` and the next `ui_state.json` save; `_closed_widget_geometry` stashes pos/size before destroying, and `spawn_widget` prefers it over centering. Session-lifetime only, not persisted to disk.
- **Media widget** (`src/ui/clMediaWidget.py`, two live copies: the dashboard widget and the calendar carousel's — `clUI.py` feeds both): the header is the badge followed by shuffle and repeat (bare icon + on-dot, no circle — `DotToggleButton(circle=False)`); the transport row is prev/play/next; the progress bar is a clickable `SeekBar` (still a 0–1000 `QProgressBar`; thicker track and knob on hover, no time tooltip); and a bottom row of three circles — Up Next, lyrics (middle, slightly bigger), App Volume — replaced the old full-width "App Volume ▾" tab. `DotToggleButton` is hand-painted so the on-dot can sit under the icon; `centered=False` drops the room above it (used where vertical padding matters: the bottom row and the header, whose badge is top-aligned to share the icons' centre line). Up Next and App Volume are drawers that grow the wrapper downward through the same `_toggle_drawer` delta logic (one open at a time; `_app_volume_delta` is shared by whichever is open; use `isHidden()`, not `isVisible()`, for drawer state). Shuffle/repeat/`can_seek` arrive in `media_status`; a click flips the button optimistically and holds a dimmed icon with a hollow dot until a status carries the requested value (or ~2.5s), so a stale status can't flip it back. Up Next is fed by the retained `jarvis/sys/spotify_queue`; opening the drawer sends `queue` (free when `clSpotify.py` already follows the queue) and its refresh button sends `queue_refresh` (the only call that costs a Web API request). Minimum width is the widest of every state (`_measure_drawers_min_width`, from throwaway sample rows, so it's the same before any data arrives): opening a drawer never widens the widget. Minimum *height* still follows the open drawer on purpose. Known, pre-existing: after App Volume rows arrive the wrapper grows to its preferred height but only the tracked delta is removed on close, so it can end up taller than before (reproduces on the original code); the grow-only `DraggableWidget` logic owns that. Backend details: `docs/context/cross-platform.md`. The drawer also has a slim always-visible `MediaPill` (`ui/clDrawerControls.py`: title/artist, previous, play/pause) fed from the same status in `_handle_media_status` and sending the same `spotify.control` `toggle`/`prev`; the full widget stays behind the dock's Media icon for the drawers. The calendar/drawer layout is in `docs/context/calendar.md`.
- **Clock** (`src/ui/clClockDisplay.py`, `ClockDisplay`): date and time centred above the visualizer's orb in fullscreen — the time's box starts 258 px down at 1080p (scaled), 84 px digits, seconds small at the right, a fading hairline, then the date line (design: the "Dashboard Clock" artboard). A plain child of `JarvisUI` created right after the visualizer (stacks above it, below every widget made later), hand-painted (Qt has no text-shadow blur, so the glow is a real gaussian — `gaussian_blur` in numpy over a mask of the digits, two layers — computed once per minute and cached; an earlier version repeated the text at a few radii and the opacity steps were visible), transparent to the mouse, and its timer (aimed at the next second, or minute with seconds off) only runs while it's shown. `refresh_layout` places it; `set_ui_mode` shows it with the fullscreen layout and hides it with the overlay square and during a monitor swap. The colon is deliberately steady (tested). `core.json` → `settings.clock_settings` (all keys optional; wrong types fall back): `enabled`, `hour24` (default true), `seconds` (true), `language` (`en`|`pt`, default `en`), `glow` (0–3, default 1.0: the halo behind the digits; 0 turns it off). Idle waves never reach it, but a loud peak (waves up to y≈270 at the app's maximum amplitude) can pass behind it — it stays on top.
- Persisted UI state (`data/ui_state.json`) is a single shared file, not per-display — don't point test instances of `clUI.py` at it. `tests/test_clUI.py` enforces this with an autouse `isolated_state_file` fixture that redirects `clUI.STATE_FILE` to a tmp path for every test; before it, several classes only patched it around part of their body and a pytest run left a default-sized, centered To-Do widget in the real file, which the live UI restored as open on its next restart. A new UI test file that constructs `JarvisUI` needs the same isolation.
- **Never `setParent(None)` a widget you're discarding — `hide()` + `deleteLater()` it.** A parentless widget is a top-level window, and `set_ui_mode("set_fullscreen")` hides the main window and pumps events (`processEvents`) while MQTT data can re-render the drawer: hiding a stray top-level at that moment left no visible window and Qt quit the UI ("died unexpectedly (exit code 0)", respawn loop, a new window each time). `clUI.py` now also sets `setQuitOnLastWindowClosed(False)` (only `closeEvent` quits) and `_install_exit_tracing()` records `lastWindowClosed` + the top-levels, `app.exec()`'s return code, and native crashes (`faulthandler`) in `logs/ui_fault.log`. `clJarvis.py` logs the exit code and holds a respawn for 60s after 3 deaths in 120s.
