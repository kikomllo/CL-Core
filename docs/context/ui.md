# Dashboard UI

Read when working on `src/clUI.py` or `src/ui/*Widget.py`. The Claude widget specifics are in `docs/context/claude-bridge-widget.md`.

- **UI** (`src/clUI.py`, PyQt6, plus `src/ui/*Widget.py`) is a separate desktop app that talks to the rest of the system purely over MQTT (`paho-mqtt`) — treat it as just another decoupled client, not part of the daemon process.
- **Dashboard window-flag parity** (`src/clUI.py`): the fullscreen dashboard no longer sets `WindowStaysOnTopHint` on Windows — that was only safe alongside a Windows-only background occlusion detector that auto-collapsed the dashboard back to overlay mode whenever another window came to the front, which has been removed so both platforms behave the same: fullscreen is left only via an explicit user action (keybind/voice), never automatically. The small idle overlay widget's click-through is applied immediately in `__init__` on both platforms now — Linux via Qt's `WA_TransparentForMouseEvents`/`WindowTransparentForInput` attributes, Windows via the `_set_win32_click_through` helper's raw `WS_EX_TRANSPARENT` toggle (Qt's attribute doesn't reliably apply on Windows combined with `WindowStaysOnTopHint`+`Tool`) — previously the Windows toggle only ran inside the `set_ui_mode("set_overlay")` transition, so it wasn't click-through until the first fullscreen↔overlay round-trip.
- **Font: JetBrains Mono** (SIL OFL), bundled in `assets/fonts/` and registered by `clUI._load_bundled_fonts()` so both machines render the same glyphs. `Theme` is the single source: `FONT_NAME`, `FONT_FILES` (to bundle another weight, add the file here), `FONT_FALLBACKS`, and `FONT_FAMILY` for stylesheets. Don't hard-code a family anywhere (code that did, e.g. `"Courier New"`, ignored the theme). It has ~13% taller line spacing than the DejaVu Sans Mono it replaced, so fixed-height widgets need a little headroom. `clTrayIcon.py` still draws its glyph in Arial: it runs in its own process, which never loads the bundled fonts.
- **Switching the skin from the UI**: Settings > System > "Assistant" dropdown (`jarvis` | `ultron`) writes `settings.theme` and shows "Save & Reboot Ecosystem"; the skin is applied at import, so the reboot restarts the UI and TTS together and the voice follows (`clTTS.resolve_tts_engine`). `JARVIS_THEME` in the environment still overrides the saved value. Tests: `TestThemeSetting` in `tests/test_clSettingsWidget.py`.
- **Skins (`settings.theme`: `jarvis` default | `ultron`)**: the code is written in the JARVIS orange palette and a skin *recolours* it, so there is one set of colours in the source, not two. `src/clSkin.py` (pure Python, no Qt, so the tray process uses it too) holds the deterministic mapping and `JARVIS_THEME=<skin>` overrides the setting for a run; it is applied in three places: `Theme`'s `C_*` constants (`clTheme._apply_skin`), every widget stylesheet (`clUIScalerInjector._scaled_setStyleSheet` -> `recolor_css`), and painted colours (`from clSkinQt import QColor` instead of `PyQt6.QtGui.QColor`; with `jarvis` it *is* Qt's class, so the default is untouched). Ultron maps orange/amber accents (hue 10-60, saturated) to crimson (the yellower, the lighter), cream/warm-grey to steel, dark browns to cold near-black, and leaves everything else (greens, blues, whites, greys, brand colours, status red/green) alone; it is idempotent, which matters because a stylesheet built from skinned `Theme` constants is recoloured again when set. **New UI code**: write colours in the JARVIS palette (or use `Theme.C_*`), import `QColor` from `clSkinQt`, never from PyQt6 directly, or that colour will not follow the skin. A colour that should not follow it (a status indicator) should simply not be warm. The Ultron chirp is `assets/themes/ultron/blip.wav` (`training/tools/make_theme_blip.py`; clTTS prefers `assets/themes/<theme>/blip.wav`); the tray icon is a red "U". Preview: `outputs/theme_preview_*.png`. Tests: `tests/test_clSkin.py`. **Under the Ultron skin the visualizer is replaced by a head** (`src/ui/clUltronHead.py`, used by `JarvisVisualizer` when `clSkin.ACTIVE == "ultron"`): a red dot-matrix head redrawn from the owner's pixel-art reference (32x32 `GRID`, smoothed to 64 cells), with its own halo; no waveform, rings, bloom or particles. It is never cut apart (an early concept dropped a jaw on speech and split the head). **There are three heads, picked by `settings.ultron_head` (`JARVIS_ULTRON_HEAD` overrides it; `head_kind`, `load_head`): `gap` (the default, `ui/clUltronHeadGap.py`: the procedural head whose dark centre gap opens as he talks, see below), `stages` (`UltronHead` in `clUltronHead.py`: procedural, a small idle mouth that opens in stages) and `sprite` (the owner's hand-drawn frames).** `gap` = the head as it was before the owner said the mouth looked wide open at idle and smaller when talking: the idle head shows the full dim mouth; as he talks the grille plates brighten only a little (`PLATE_GAIN`), the bar of plates under the dark notch between the two big plates climbs up into it (`GAP_RISE`) while the lower lip drops (`GAP_DROP`, metal cells below the grille light up), so the lit mouth grows both ways, and the notch gets wider; every cell is strictly lit or dark (no smoothstep: pixel art) (side plates go dark, `GAP_WIDEN`, `GAP_EDGE_DEPTH`), a seam two cells inside the jawline lights up, and the cells inside the lower face's outline swell sideways (`CHEEK_BULGE`); the outline never moves or reacts. All three share the grid, the cached metal layer, the glow, the glitch and `pulse_scale`. **The head is hand-drawn sprite frames** (`SpriteHead`, `load_head()`): `assets/themes/ultron/head/idle.png`, `talk_1.png` ... (42x58, one pixel = one dot with exactly the colour drawn; pure black or transparent = outside the head, not drawn). Frame 0 is idle, frame 1 the quietest speech, the last the loudest; the code only picks / cross-fades them by the voice (`frame_pos`: not speaking = idle; the moment he speaks, even quietly, frame 1; louder moves through the rest; `step` eases in real time, quick to open, slower to close) and adds: **brightness that rises with how open the mouth is** (`BRIGHT_LIFT`: the whole head and the mouth dots lift together, so more volume = wider mouth = brighter, always together) and **an exaggerated mouth beyond the drawn frames**: the first talking frame is never changed (nor lifted), and from there to the loudest frame the lit mouth is *stretched* (`grown`, `GROW_SX` wider, `GROW_SY` taller, about its top so it never grows up into the nose; the same shape with its lobes and its gap, because dilating it fills the gap and makes a solid block). The mouth pixels are found by colour (`MOUTH_RED` <= red < `OUTLINE_RED`, in the rows below `MOUTH_TOP`; the sprite also has a faint ring of red-88 pixels just inside the outline that must not count), the small plates beside it (cheek plates), the outline, the eyes and anything next to the outside are never touched. **The whole head pulses with the voice** (`pulse_scale`, applied in `JarvisVisualizer.paintEvent` on top of the state scale 0.8 idle / 1.0 speaking): at rest it only breathes (`BREATH`), while he speaks it is `PULSE_QUIET` at the quietest syllable up to `PULSE_LOUD` at the loudest, so it gets bigger and smaller as he talks (without it the head feels dead). The sprites are the owner's: `idle.png`, `talk_1.png`, `talk_2.png`, `talk_3.png` (re-drawn 2026-11-05; frame 3 also shifts the brows a little, which is fine: any pixel that differs between frames is just painted per frame). , the eye glow and the halo (`drive`), the glitch and the flicker. Pixels that are identical in every frame (outline, eyes, brows ...) are painted once into a cached pixmap, only the pixels that differ between frames are painted per frame. To change the animation, edit or add the PNGs (same size, same outside); with fewer than 2 frames the old procedural head (`UltronHead`: a mouth model built from the 32x32 `GRID`) is the fallback. `talk_level` is the TTS/mic amplitude the waveform used (quick attack, slower release); the cheek plates are just pixels of the sprite. Idle is the breathing; a **glitch** (`Glitch` class, time based so it is the same at 8 or 60 fps; tune with `settings.ultron_glitch`, defaults in `GLITCH_DEFAULTS`) fires a *soft* version (a few row bands sliding up to `soft_shift` cells for `soft_ms`) at random gaps at rest (`idle_every_s`), rarer while speaking, often while processing, plus a rare *hard flicker* (`hard_every_s`, `hard_ms`: more and taller bands, up to `hard_shift` cells, the whole head stuttering in brightness, sometimes near-off) at a random moment; `enabled: false` turns it off. The dim metal is painted once per size into a pixmap, so a frame draws only a few hundred dots (plates, gap, lower face); pure numpy, no scipy in the UI process; raw `QColor` on purpose (the skin's recolouring would turn the dim reds near-black). Tests: `tests/test_clUltronHead.py`, `tests/test_clUltronHeadMotion.py` (the painted-pixel helper must `.copy()` the image buffer). Preview: `outputs/ultron_head_visualizer.png`.
- **Rounded borders are painted by `src/clSmoothBorders.py`, not by Qt.** Qt's QSS draws a `border` on a rounded widget from clipped arc segments (stepped, lopsided corners; worst pixel ~135/255 off an ideal corner; a fill with no border is fine, ~13). The 1920x1080 / 100% monitors have no spare resolution to hide it. The engine hooks every `QWidget.setStyleSheet` (via `clUIScalerInjector`) plus `QPushButton`/`QLineEdit` creation (the global stylesheet styles those with no per-widget sheet). For a widget whose cascade (application < ancestors < own sheet; `parse_css`/`resolve` handle `Type#id:pseudo` selectors and bare declarations only) gives it a radius and a solid border, the sheet handed to Qt gets a marked override block making the border colour `transparent` (same width, so layout is unchanged), and the widget's `paintEvent` is wrapped to paint the border afterwards as one AA ring path, per state (hover/pressed/checked/disabled/focus) and per side (the event cards' thick orange left edge). Gotchas: the override selector must be `QWidget#name` placed last (it ties on specificity and wins by order; a repeated id or an attribute selector does NOT raise Qt's specificity); `styleSheet()` returns the sheet with the block, so callers that re-read it are fine (`_OVERRIDE_BLOCK` strips it on the next set); widgets given no `objectName` get `sbN`; margins, non-solid borders, gradient border colours and `QTextEdit`/scroll areas are left to Qt. Debug switch: `JARVIS_SMOOTH_BORDERS=0` turns it off. Small circles are hand-painted instead: `ui/clRingCheckBox.py` (`RingCheckBox`, the To-Do checkbox: 8x supersample, box-filtered, cached) and `DotToggleButton` in `clMediaWidget.py`. A new rounded widget needs nothing special; just don't draw its border any other way.
- **Responsive layout (any resolution, either orientation; tests: `tests/test_clResponsiveLayout.py`).** The rules mirror a website's. (1) *One fluid unit*: `UIScaler.scale_for(w, h) = min(long/1920, short/1080)`, so a screen has the same scale turned either way (1080x1920 is 1.0; the old `min(w/1920, h/1080)` gave 0.56 and shrank everything to a strip). Landscape is unchanged. (2) *Wrap at a breakpoint*: `refresh_layout` puts the widget dock in the margin beside the text bar; when that margin is narrower than the dock (`layout_compact`) the dock wraps onto its own row centred above the bar, the audio pills and lyrics stack above it, and the reminder popup goes top-right. The bar, lyrics, reminder popup and calendar drawer are capped to the window (`max-width: 100%`). (3) *Anchor to the orb, not the top*: the clock is placed from the window's vertical centre, so it stays the same distance above the head on any aspect ratio. (4) *Widgets stay in view*: `_fit_widgets_to_window` (end of `refresh_layout`) remaps pinned widgets proportionally when the canvas changes (a monitor swap) with sizes following the scale uniformly, then clamps each fully inside the window; `load_ui_state` does the same on restore (it used to stretch sizes per axis). It does nothing until the window is fullscreen-sized (the overlay box would crush positions to (0,0)). **Gotcha: `QWidget.resize` is patched to multiply by the UI scale** (`clUIScalerInjector`), so any call that already has physical pixels (a screen's geometry, `sizeHint()`, a saved size) must use `resizeUnscaled`; `resize()` there made the fullscreen window 971x546 on a 1366x768 monitor and 607x1080 on a 1080x1920 one. New layout code: place things from `win_w`/`win_h` and `s()`, never from 1920x1080 constants.
- **A widget can save extra state of its own** (`save_ui_state` stores `"state": content_widget.get_ui_state()` per widget when it has one; `load_ui_state` hands it back through `restore_ui_state(state)`). The media widget uses it to keep its open drawer across a UI restart: `{"drawer": "queue"|"app_volume"|None, "drawer_delta": px}`. **`restore_ui_state` runs BEFORE `load_ui_state` resizes the wrapper**, and it shows the drawer without growing the wrapper: the saved size already includes the drawer's height, and a `setVisible(True)` after the resize would make Qt auto-grow the window a second time (the saved delta is scaled by the UI-scale ratio like the size, and later content changes are re-measured by `_sync_app_volume_drawer_size`). Toggling a drawer or the lyrics switch saves the layout straight away (`_persist_ui_state`, a no-op for the calendar carousel's copy, which has no wrapper, and while a restore is running). `settings`-level `lyrics_enabled` is saved with the layout too (carried forward from disk when saving from overlay, like the rest). Tests: `TestDrawerStateSurvivesARestart` (`test_clMediaWidget.py`), `TestMediaDrawerStateSurvivesAUiRestart` (`test_clUI.py`: patch `ActionRouter.dispatch`, the restore asks the broker for the queue/apps).
- **Monitors: a restart returns to the saved monitor, and every monitor keeps its own layout (tests: `TestEachMonitorKeepsItsOwnLayout`, `TestOverlappingWidgetsArePacked`).** (1) With `JARVIS_REBOOT=1` the dashboard reopens on `current_monitor_idx` (stable order, `UIScaler.get_stable_screens`) when that screen still has the size saved in `screen_size`; only otherwise (or on a first, user-started fullscreen) is it the screen under the mouse. `load_ui_state` no longer overwrites the monitor index `set_ui_mode` picked once fullscreen. (2) `ui_state.json` has `layouts: {"<screen name>|<w>x<h>": {widget id: {pos, size}}}` next to the old top-level fields (those stay "the last screen used", and a file without `layouts` is migrated: its top-level geometry belongs to `current_monitor_idx`/`screen_size`). Positions are pixels of THAT screen, so `load_ui_state` and a monitor swap (`_fit_widgets_to_window`) restore a screen's own layout exactly; only a screen with no saved layout falls back to remapping another's (sizes follow the UI scale uniformly, positions proportionally), and then `_resolve_widget_overlaps` packs any widgets that now sit on top of each other into rows, left to right, wrapping at the window width (a layout that does not overlap is never touched). Only pinned widgets are in a layout (an unpinned one has global coordinates). (3) `save_ui_state` does nothing while `_is_swapping_monitors` (every widget is hidden and still holds the OLD screen's geometry, which used to overwrite the new screen's layout); the swap saves once when it is done. (4) **Windows lands `showFullScreen()` on the PRIMARY monitor for a window that was never shown, whatever `move()`/`windowHandle().setScreen()` said** (reproduced with transparent probe windows: it is why a restart, and the monitor swap, opened on the wrong screen). Fix in `set_ui_mode`: on a non-swap start `show()` normally on the target screen first, then `showFullScreen()`, then `_land_on_target_screen` re-asserts once (`showNormal`, `setScreen`, `setGeometry`, `showFullScreen`) if it still landed elsewhere; `_on_target_screen()` stops a window on the wrong screen from saving a layout under that screen's key. The swap saves the screen it leaves BEFORE the index moves on, and once more when it is done (about 10 s later). A test that needs a fullscreen-sized window must lift the overlay box's fixed size first (`setMinimumSize(0, 0)` / `setMaximumSize(16777215, 16777215)`, as `set_ui_mode` does) and pin `screen()`/`_target_screen()`.
- **The Live Logs widget (`src/ui/clLogWidget.py`) must never load the log whole.** `logs/latest_run.log` is many MB with single lines of tens of KB (lyrics JSON), and the widget runs on the UI thread: inserting all of it took ~5 s on open (growing every run) and froze the UI. It now opens with only the last `INITIAL_TAIL_BYTES` (starting on a whole line), one poll reads at most `MAX_READ_BYTES` (a bigger burst shows its tail plus a "KB of log skipped" note), only whole lines are consumed (a line still being written waits), lines are cut (see below), the document keeps the last `MAX_BLOCKS` lines (undo off), a truncated log (a new run) starts over, and the 500 ms poll stops while the widget is hidden (the dashboard hides it, it does not destroy it) and catches up on show. Never schedule a deferred call with a lambda that captures a child widget (`QTimer.singleShot(0, lambda: scrollbar...)` crashed the test process with an access violation once the widget was gone): use a bound method of the widget. **Condensed by default**: the shared, Qt-free `src/utils/clLogTail.py` (`condense`, `LogTailer`) is a view over the log, never a change to it: it drops heartbeat topics (`NOISY_TOPICS`: audio_vol, media/spotify status echoes, tts_ref, lyrics, queue, the todo poll) and protocol chatter (paho CONNECT/PUBLISH, urllib3, AUMID lookups, Tapo handshakes, `[DEBUG KEY/LAYOUT]`), collapses the doubled timestamp, cuts lines to `LINE_CHARS` (an MQTT payload to `PAYLOAD_CHARS`, a Spotify API dump to its first `RESULTS_CHARS`), turns a Spotify request into `GET /v1/...` without its headers, and redacts `Bearer` tokens in both modes (the real log took 12 MB to 370 KB, 16k lines to 3.7k). New noise: add its topic or regex there, with a test. The header's **Condensed** toggle switches to the raw view (still cut at `RAW_LINE_CHARS`) and reloads the tail; **Open terminal** runs `python src/utils/clLogTail.py [--raw]` in its own console (`CREATE_NEW_CONSOLE` on Windows, the first of x-terminal-emulator/gnome-terminal/konsole/xfce4-terminal/xterm on Linux; a console needs `python.exe`, so `pythonw.exe` is swapped) in the same mode as the view, and the button says so if no terminal exists. Tests: `tests/test_clLogWidget.py`, `tests/test_clLogTail.py`.
- **Capsule pills (`IconPill`: the audio and dock pills) need a radius that is half their height AFTER scaling**, so it comes from `IconPill._capsule_radius()` (design px, never scaling past `diameter / 2`). A stylesheet is scaled when set, so passing the physical `diameter // 2` scaled it twice: below scale 1.0 the expanded pill got squarish ends (a black square around the icon circle that popped in as the hover expansion started, read as a flicker), above 1.0 Qt drew the oversized radius as sharp corners. Test: `test_the_expanded_pill_keeps_round_ends_at_every_ui_scale`.
- **Closed widgets remember their geometry for the session.** `close_draggable_widget` destroys the wrapper, so its position drops out of `active_widgets` and the next `ui_state.json` save; `_closed_widget_geometry` stashes pos/size before destroying, and `spawn_widget` prefers it over centering. Session-lifetime only, not persisted to disk.
- **Media widget** (`src/ui/clMediaWidget.py`, two live copies: the dashboard widget and the calendar carousel's — `clUI.py` feeds both): the header is the badge followed by shuffle and repeat (bare icon + on-dot, no circle — `DotToggleButton(circle=False)`); the transport row is prev/play/next; the progress bar is a clickable `SeekBar` (still a 0–1000 `QProgressBar`; thicker track and knob on hover, no time tooltip); and a bottom row of three circles — Up Next, lyrics (middle, slightly bigger), App Volume — replaced the old full-width "App Volume ▾" tab. `DotToggleButton` is hand-painted so the on-dot can sit under the icon; `centered=False` drops the room above it (used where vertical padding matters: the bottom row and the header, whose badge is top-aligned to share the icons' centre line). Up Next and App Volume are drawers that grow the wrapper downward through the same `_toggle_drawer` delta logic (one open at a time; `_app_volume_delta` is shared by whichever is open; use `isHidden()`, not `isVisible()`, for drawer state). Shuffle/repeat/`can_seek` arrive in `media_status`; a click flips the button optimistically and holds a dimmed icon with a hollow dot until a status carries the requested value (or ~2.5s), so a stale status can't flip it back. Up Next is fed by the retained `jarvis/sys/spotify_queue`; opening the drawer sends `queue` (free when `clSpotify.py` already follows the queue) and its refresh button sends `queue_refresh` (the only call that costs a Web API request). **Each Up Next row is a `QueueRow` button**: a click anywhere on it sends `play_queue_item` (`uri` + `queue_index`) and the rows dim ("switching...") until the retained queue message comes back without the tracks it jumped over (4 s timeout; a second click is ignored meanwhile; a row from an older payload without a `uri` isn't clickable). The backend can't "play this entry" through the Web API (starting the uri alone would replace the playlist), so it presses Next index+1 times; see `docs/context/cross-platform.md`. Minimum width is the widest of every state (`_measure_drawers_min_width`, from throwaway sample rows, so it's the same before any data arrives): opening a drawer never widens the widget. Minimum *height* still follows the open drawer on purpose. Known, pre-existing: after App Volume rows arrive the wrapper grows to its preferred height but only the tracked delta is removed on close, so it can end up taller than before (reproduces on the original code); the grow-only `DraggableWidget` logic owns that. Backend details: `docs/context/cross-platform.md`. The drawer also has a slim always-visible `MediaPill` (`ui/clDrawerControls.py`: title/artist, previous, play/pause) fed from the same status in `_handle_media_status` and sending the same `spotify.control` `toggle`/`prev`; the full widget stays behind the dock's Media icon for the drawers. The calendar/drawer layout is in `docs/context/calendar.md`.
- **Clock** (`src/ui/clClockDisplay.py`, `ClockDisplay`): date and time centred above the visualizer's orb in fullscreen — the time's box starts 258 px down at 1080p (scaled), 84 px digits, seconds small at the right, a fading hairline, then the date line (design: the "Dashboard Clock" artboard). A plain child of `JarvisUI` created right after the visualizer (stacks above it, below every widget made later), hand-painted (Qt has no text-shadow blur, so the glow is a real gaussian — `gaussian_blur` in numpy over a mask of the digits, two layers — computed once per minute and cached; an earlier version repeated the text at a few radii and the opacity steps were visible), transparent to the mouse, and its timer (aimed at the next second, or minute with seconds off) only runs while it's shown. `refresh_layout` places it; `set_ui_mode` shows it with the fullscreen layout and hides it with the overlay square and during a monitor swap. The colon is deliberately steady (tested). `core.json` → `settings.clock_settings` (all keys optional; wrong types fall back): `enabled`, `hour24` (default true), `seconds` (true), `language` (`en`|`pt`, default `en`), `glow` (0–3, default 1.0: the halo behind the digits; 0 turns it off). Idle waves never reach it, but a loud peak (waves up to y≈270 at the app's maximum amplitude) can pass behind it — it stays on top.
- Persisted UI state (`data/ui_state.json`) is a single shared file, not per-display — don't point test instances of `clUI.py` at it. `tests/test_clUI.py` enforces this with an autouse `isolated_state_file` fixture that redirects `clUI.STATE_FILE` to a tmp path for every test; before it, several classes only patched it around part of their body and a pytest run left a default-sized, centered To-Do widget in the real file, which the live UI restored as open on its next restart. A new UI test file that constructs `JarvisUI` needs the same isolation.
- **Never `setParent(None)` a widget you're discarding — `hide()` + `deleteLater()` it.** A parentless widget is a top-level window, and `set_ui_mode("set_fullscreen")` hides the main window and pumps events (`processEvents`) while MQTT data can re-render the drawer: hiding a stray top-level at that moment left no visible window and Qt quit the UI ("died unexpectedly (exit code 0)", respawn loop, a new window each time). `clUI.py` now also sets `setQuitOnLastWindowClosed(False)` (only `closeEvent` quits) and `_install_exit_tracing()` records `lastWindowClosed` + the top-levels, `app.exec()`'s return code, and native crashes (`faulthandler`) in `logs/ui_fault.log`. `clJarvis.py` logs the exit code and holds a respawn for 60s after 3 deaths in 120s.
- **The To-Do widget (`src/ui/clTodoWidget.py`) syncs its rows in place on every status refresh; never rebuild them.** `update_status` used to `tabs.clear()` and recreate every row for every change (a task added, ticked or deleted): all rows were unlaid-out for ~200 ms (squeezed to their minimum height, text of neighbours overlapping, then spread out again, on every add, seen live with 28 items) and each refresh leaked the old pages (`QTabWidget.clear()`/`removeTab()` do not delete the page: `deleteLater()` it). Now `_sync_rows` keeps rows by task id: unchanged rows are not touched, new ones are inserted before the one trailing spacer, gone ones are `deleteLater()`d, a changed task updates its label/checkbox (checkbox signals blocked, so no toggle is sent back) and a moved one (completed tasks sort last) is re-inserted; a row's right-click handler reads its *current* `completed`, since rows are reused. Only a burst of many new rows at once (the first load) still shows the short settle. Tests: `TestRefreshUpdatesRowsInPlace` in `tests/test_clTodoWidget.py`.
- **Light colour button** (`src/ui/clColourPicker.py`, wired in `src/ui/clLightControlWidget.py`): each Smart Lights row with colour has a round `ColourButton` showing the light's own colour (its `rgb`, or the tint of its `kelvin`; dim while off, disabled while offline) that opens a `ColourPicker` *popup window* (`Qt.Popup`: it overhangs the small widget and closes on an outside click or Escape; `WA_DeleteOnClose`). **The popup is a transparent window holding one styled `QFrame`**: a stylesheet background set on the translucent top-level itself is not painted (measured: the popup came out see-through). **Swatches, the white-temperature track and the button's dot are painted by hand with raw `PyQt6.QtGui.QColor`** (a bulb's real colours must not follow the skin: under Ultron an orange swatch would turn red); only the chrome uses `clSkinQt.QColor`/`Theme`. The picker never talks to the lights: it emits `chosen(fields)` (`color` / `temp` / `lum`) and the widget sends `light.set` with `action: on` (a colour also turns the light on), then updates the button at once; the next `light_status` confirms. Sliders send 200 ms after the value settles (and on close), not per pixel. Swatch names are voice colour names from `config/entities.json` (`tests/test_clColourPicker.py` keeps them in step). Tests: `tests/test_clColourPicker.py`, `TestColourButton`/`TestColourPopup` in `tests/test_clLightControlWidget.py`. **Customisable swatches:** right-click a colour swatch opens `ColourWheelPopup` (a `ColourWheel`, painted raw like the swatches); a drag recolours the bulb live and the swatch, `ColourPicker.swatchChanged(name, rgb|None)` tells the widget to save it (`clWebSettings.apply`, core.json `settings.light_swatches`, shared with the web picker); a changed swatch sends `rgb`, a default one its voice name.
